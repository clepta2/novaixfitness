Estas são as diretrizes de conformidade jurídica internacional e proteção de segredos que transformam o seu aplicativo em um ecossistema blindado contra espionagem governamental, fiscalizações e vazamentos em massa:

141. Criptografia em Nível de Linha no Banco (Application-Layer Encryption)
Por padrão, o Supabase criptografa o banco de dados inteiro no disco rígido deles (criptografia em repouso). Porém, se um hacker conseguir um acesso administrativo direto ao painel do banco de dados (ou se um funcionário mal-intencionado com acesso ao banco resolver bisbilhotar), ele conseguirá ler os dados dos clientes em texto puro.

A Regra: Dados ultra-sensíveis (como prontuários de anamnese física do Novais Fitness, faturamento e tokens privados de integração) devem ser criptografados pelo Node.js antes de serem enviados ao Supabase.

O Correto: Use a biblioteca nativa crypto do Node para criptografar o dado com uma chave AES-256-GCM trancada no seu .env. No Supabase, o dado fica salvo como um texto embaralhado e ilegível (ex: g4jK9L0...). Mesmo que o banco vaze por completo na internet, ninguém conseguirá ler os dados sem a chave secreta que só a sua VPS possui.

142. Ofuscação e Proteção do Código React (Anti-Reverse Engineering)
O código que você escreve no React vai direto para o navegador ou celular do cliente. Se você deixar o código aberto e fácil de ler, um concorrente ou um hacker pode baixar o seu arquivo .js, ler a lógica inteira das suas telas, mapear as rotas da sua API e copiar os diferenciais do seu aplicativo.

A Regra: O build de produção do React deve passar obrigatoriamente por um processo de minificação extrema e ofuscação de código.

O Correto: Configure o seu empacotador (Vite/Webpack) para remover todos os comentários, logs de console e renomear variáveis e funções para letras aleatórias (ex: function calcularPontos() vira function a()). Além disso, desative a geração de Source Maps em produção para impedir que ferramentas de desenvolvedor reconstruam o seu código original.

143. O Princípio do "Direito ao Esquecimento" Automático (LGPD/GDPR Compliance)
Pelas leis de proteção de dados (LGPD no Brasil), se um usuário solicitar a exclusão da conta dele, você é obrigado a apagar todos os dados pessoais dele do sistema de forma definitiva. Se você apenas mudar o status dele para "inativo" no banco e guardar os dados, você estará cometendo uma infração gravíssima passível de multas pesadas.

A Regra: A rota DELETE /api/perfil deve disparar uma deleção em cascata real no Supabase.

O Correto: O banco executa o apagamento dos dados de perfil, limpa os caches de identificação no Redis e remove fisicamente os arquivos do Storage. Para dados que você é obrigado por lei a guardar (como o histórico de notas fiscais ou vendas no Asaas por motivos fiscais), você deve aplicar a Anonimização: apaga-se o nome, e-mail e CPF do cliente, substituindo-os por [USUÁRIO DELETADO], mantendo apenas o registro numérico do valor do imposto para o governo.

144. Mascaramento Dinâmico de PII em Telas (Data Masking)
Se um técnico ou administrador do seu sistema estiver usando o painel de gestão em um local público (como na recepção do Instituto Mix ou na Diff Store) e alguém olhar por cima do ombro dele, essa pessoa poderá ver CPFs, telefones e faturamentos inteiros expostos na tela.

A Regra: Dados de identificação pessoal (PII) nunca devem ser exibidos de forma escancarada por padrão no React.

O Correto: No front-end, aplique máscaras visuais que escondem a maior parte do dado (ex: exibindo um telefone como (13) 9****-1234 ou e-mail como jef*****@gmail.com). O dado real só é revelado na tela se o administrador clicar explicitamente em um ícone de "olho" para visualizar, gerando um log interno na tabela de auditoria (Regra de Auditoria).

145. Rotação Automática de Chaves Secretas (Secret Rotation Strategy)
Por mais seguro que você seja, chaves de API antigas (como o token do Asaas ou as credenciais do Supabase) que ficam salvas no arquivo .env por anos aumentam a chance de vazamento por descuido técnico (como salvar o arquivo .env sem querer em um backup desprotegido).

A Regra: Chaves de integração e chaves criptográficas devem ter um plano de troca periódica obrigatória.

O Correto: A cada 6 meses ou 1 ano, você deve entrar no painel do Asaas e do Supabase, gerar um novo token de acesso, atualizar o arquivo .env na VPS da Hostinger e reiniciar os containers Docker com o comando docker compose up -d --force-recreate. O token antigo é revogado instantaneamente, invalidando qualquer chave velha que possa ter vazado no passado.
