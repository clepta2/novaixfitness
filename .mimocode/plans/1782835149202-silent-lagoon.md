# Plano: Regras de Seguranca para Codigo + Aplicacao dos 4 Conceitos Avancados

## Contexto

O usuario criou uma pasta `regras/seguranca/` com um guia de 4 conceitos avancados:
1. Zero-Knowledge Architecture (criptografia client-side)
2. API Idempotency (chaves de idempotencia em pagamentos)
3. JWT Revocation com Blocklist (tokens de curta vida + refresh)
4. Cryptographic Agility & Secret Rotation (rotacao de chaves)

A exploracao do codigo revelou **vulnerabilidades criticas** que precisam ser corrigidas:
- Criptografia **falsa** em 2 arquivos (retorna hash, nao dados reversiveis)
- Webhook token **estatico e fraco** (`Loja195@`)
- Servico de idempotencia **existe mas nao esta conectado**
- Dados sensiveis **armazenados em plaintext**
- Rate limiting **bypassavel** (so client-side)
- Secrets **expostos em .env no disco**
- Root detection **stub vazio**
- Fallback para `Math.random()` em crypto

## O que sera feito

### 1. Criar `regras/seguranca/REGRAS_SEGURANCA.md` — Regras obrigatorias para IA de codigo
Arquivo de regras que impoe padroes de seguranca que a IA deve seguir ao criar/modificar codigo. Inclui:
- Nunca usar criptografia falsa (hash != encrypt)
- Sempre usar idempotency key em chamadas financeiras
- JWT com TTL curto + refresh tokens
- Secret rotation pattern
- Validacao de webhook com HMAC, nao string
- Nunca expor secrets em codigo
- Rate limiting server-side obrigatorio
- Input sanitization em todo boundary

### 2. Corrigir `src/services/security/encryptionField.ts` — Criptografia real
- Substituir SHA256 (one-way) por AES-GCM-256 (reversivel)
- Usar chave derivada da senha do usuario (PBKDF2/scrypt)
- Garantir que decrypt retorna o dado original

### 3. Corrigir `src/services/security/dataProtection.ts` — Criptografia real
- Substituir prefixo `encrypted_` por criptografia simetrica real
- Usar a mesma infra de encryptionField

### 4. Conectar `backend/src/routes/webhooks.ts` ao `webhookIdempotency.ts`
- Importar e usar o servico de idempotencia que ja existe
- Adicionar Idempotency-Key em chamadas ao Asaas

### 5. Melhorar webhook security
- Substituir token estatico por verificacao HMAC-SHA256
- Adicionar validacao de assinatura no webhook handler

### 6. Implementar JWT blocklist (quando Supabase nao gerencia)
- Criar middleware que verifica blocklist antes de aceitar token
- Suporte para revogacao em tempo real

### 7. Adicionar rate limiting server-side
- Middleware no backend que bloqueia IPs/usuarios com excesso de chamadas
- Complementar o client-side que ja existe

### 8. Fixar `src/services/rootDetection.ts`
- Implementar deteccao real de root/jailbreak em vez de stub

### 9. Fixar `src/utils/securityAdvanced.ts`
- Remover fallback para Math.random()
- Usar crypto seguro sempre

### 10. Criar testes para todas as mudancas
- Testes de criptografia real (encrypt → decrypt roundtrip)
- Testes de idempotencia
- Testes de webhook HMAC
- Testes de JWT blocklist
